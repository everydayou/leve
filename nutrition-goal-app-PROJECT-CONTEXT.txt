0B. DESIGN-SYSTEM CONTRACT — FIXED RULES (read BEFORE editing any UI)
----------------------------------------------------------------
Non-negotiable standing rules. Any chat touching src/ui MUST follow them.

1. COMPONENTS FIRST. Build UI from kit atoms in src/ui/kit: Button/IconButton,
   Sheet, LabeledInput, NumberField, Card/Surface, StatTile, ProgressBar/
   GaugeArc, Badge, SegmentedControl, FilterPills, Icon, etc. NEVER hand-roll
   a button/input/sheet/stat inline when a kit atom exists.
2. TOKENS ONLY. Colour, radius, shadow and type from src/index.css semantic
   tokens. NEVER raw Tailwind text sizes (text-xs/sm/base/lg/xl) — use
   text-caption/footnote/subhead/body/callout/headline/title/display/hero.
   NEVER hardcode hex/rgb — use colour tokens.
3. ICONS, NOT GLYPHS. Use <Icon> for all affordances. Never type ›, ‹ or ×.
4. ONE SOURCE OF TRUTH. Change look via token or atom, never per-screen CSS.
5. ENFORCEMENT. eslint.config.js BLOCKS raw text sizes and hex/rgb in src/ui.
   Run `npm run lint` before shipping. Do NOT disable guardrails.
6. ACCESSIBILITY FIRST. Focus outlines, ARIA roles, prefersReducedMotion(),
   WCAG AA contrast, 44×44pt touch targets, labeled form inputs.

Text scale: caption(12) / footnote(13) / subhead(15) / callout(16) /
headline(18) / title(22) / display(30) / hero(48).
WHERE THINGS LIVE: tokens = src/index.css (@theme); atoms = src/ui/kit/;
live reference = /styleguide route.

----------------------------------------------------------------
1. WHAT WE'RE BUILDING
----------------------------------------------------------------
A personal nutrition + weight-management app for Marco's own use.
NOT a calorie tracker. Core idea: GOAL MANAGEMENT — tracking exists only
to answer "Am I on track to hit my goal?"
Mental model: Goal → Weekly progress → Daily progress → Food/Activity inputs.

----------------------------------------------------------------
2. PLATFORM & STACK
----------------------------------------------------------------
React + Capacitor (web code + native iOS shell). NOT native Swift.
Stack: Vite 6, React 19, TypeScript, Tailwind CSS v4, Dexie (IndexedDB),
Vitest. Capacitor v8. appId: com.marco.nutritiongoal, webDir: dist.
Install path: Xcode + free Apple ID ($0). Re-sign every ~7 days.

----------------------------------------------------------------
3. AGREED V1 SCOPE
----------------------------------------------------------------
- Goal types: lose_by_date and gain_by_date.
- TODAY: frequent foods, Add-entry sheet, calories + protein, deficit,
  swipeable day nav.
- GOAL: weight trend vs. target line, 9 lifecycle states.

4B. V1 DATA MODEL
----------------------------------------------------------------
Goal status: active / completed / abandoned.
GoalScreen renders 9 states (all implemented r55):
  (1) no-goal  (2) active-normal  (3) final-day·no-weight
  (4) final-day·weight-in(not hit)  (5) final-day·goal-hit
  (6) early-complete  (7) overdue  (8) completed  (9) abandoned/ended
GoalOutcomeView: createPortal → document.body. Slide-up on mount.
GoalSettingsSheet (⋯): Mark complete / Edit plan / End goal / Past goals.
User model: weightCadence ('daily'|'weekly'), weeklyWeightDay.

----------------------------------------------------------------
5. METRICS / MATH
----------------------------------------------------------------
Total Burn = BMR + Active Calories.
Daily Deficit = Total Burn − Calories Consumed.
~7700 kcal per kg for goal pace math.

ROUND 132 — CONVERT-TO-MEAL: STALE foodItemId HID EVERY OTHER ITEM (2026-07-02)
Files: src/ui/components/AddEntrySheet.tsx
Root cause of round 131's open item: converting a plain Food entry into a
Meal (save()'s meal branch) set mealId but never cleared the entry's OLD
foodItemId. entryToBasket() checked foodItemId before mealData, so reopening
a converted entry rebuilt a single-item basket from the stale link — while
the Day's-log LIST ROW (via effectiveNutrition(), which already checks
mealData first per round 123) correctly showed the combined total. That
split (right total, wrong reopen) was the tell.
Fixed both ends: entryToBasket() now checks mealData first (matching
effectiveNutrition()'s order); save()'s meal branch explicitly clears
foodItemId on conversion.
Nutri-scan: not a code bug — the described result (per_100g, qty = estimated
grams, no serving prompt) is exactly how Camera/Photo scanning behaves by
design; the dedicated Nutri-scan (label) button does prompt via
ServingModal. Confirming with Marco which icon he actually used.
tsc: clean. lint: clean. vitest: 35 passed. `npm run build` verified clean.

ROUND 131 — DAY'S-LOG EDIT FLOW: LIVE-LINK BUGS (2026-07-03)
Files: src/ui/components/AddEntrySheet.tsx
Marco's testing surfaced pre-existing bugs (not introduced by the meals-in-
pantry work) in how editing a Day's-log basket item talks to the Pantry:
- Editing an ALREADY pantry-linked item's macros never wrote through to
  repos.foodItems — the "save to pantry" checkbox is hidden once an item is
  already linked, and both EditOverlay onSave handlers used that checkbox
  value (always false when hidden) to gate the write. Fixed: write-through
  now happens whenever the item IS or BECOMES linked; the checkbox only
  gates whether a brand-new item gets linked in the first place.
- Newly-linking a manual entry to pantry (LogEntryContent) set foodItemId
  but never quantity — effectiveNutrition() needs both to live-recompute,
  so the entry looked linked but stayed frozen on its old snapshot forever.
  This explains Marco's exact repro: today's entry (added via search, which
  sets quantity) updated correctly; a past entry retrofitted via edit →
  save-to-pantry (missing quantity) never did.
- Outer "Save changes" compared against a stale `pantryItem` prop (resolved
  once at mount) instead of the live basket state — could lose a link
  created mid-session. Now checks basket[0].pantryItemId directly.
- Switching measurementType during an edit (per_100g <-> per_serving) left
  the old qty number as-is, reinterpreting grams as servings or vice versa
  (Marco's screenshot: 8.9g became "8.9 srv"). Now resets qty to a sensible
  default when the unit actually changes.
- LogEntrySheet's title is now "Food item"/"Meal" (generic, matching the
  Pantry's own screens per Marco's original reference), reactive to the
  live basket size — not the entry's actual name.
- Also removed 4 stray now-unused eslint-disable comments surfaced by
  nearby code shifting.
- tsc: clean. lint: clean (0 warnings). vitest: 35 passed. `npm run build`
  verified clean.
- STILL OPEN (need more specific repro): "convert an existing Food entry to
  a Meal, then Save — not working" (code review didn't find a distinct bug
  beyond the ones above — may already be fixed by them, needs retest); and
  the Nutri-scan flow not prompting per-100g/per-serving on a specific scan.
