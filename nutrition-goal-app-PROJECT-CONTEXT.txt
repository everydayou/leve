0B. DESIGN-SYSTEM CONTRACT — FIXED RULES (read BEFORE editing any UI)
----------------------------------------------------------------
Non-negotiable standing rules. Any chat touching src/ui MUST follow them.

1. COMPONENTS FIRST. Build UI from kit atoms in src/ui/kit: Button/IconButton,
   Sheet, LabeledInput, NumberField, Card/Surface, StatTile, ProgressBar/
   GaugeArc, Badge, SegmentedControl, FilterPills, Icon, etc. NEVER hand-roll
   a button/input/sheet/stat inline when a kit atom exists.
2. TOKENS ONLY. Colour, radius, shadow and type from src/index.css semantic
   tokens. NEVER raw Tailwind text sizes (text-xs/sm/base/lg/xl) — use
   text-caption/footnote/subhead/body/callout/headline/title/display/hero.
   NEVER hardcode hex/rgb — use colour tokens.
3. ICONS, NOT GLYPHS. Use <Icon> for all affordances. Never type ›, ‹ or ×.
4. ONE SOURCE OF TRUTH. Change look via token or atom, never per-screen CSS.
5. ENFORCEMENT. eslint.config.js BLOCKS raw text sizes and hex/rgb in src/ui.
   Run `npm run lint` before shipping. Do NOT disable guardrails.
6. ACCESSIBILITY FIRST. Focus outlines, ARIA roles, prefersReducedMotion(),
   WCAG AA contrast, 44×44pt touch targets, labeled form inputs.

Text scale: caption(12) / footnote(13) / subhead(15) / callout(16) /
headline(18) / title(22) / display(30) / hero(48).
WHERE THINGS LIVE: tokens = src/index.css (@theme); atoms = src/ui/kit/;
live reference = /styleguide route.

----------------------------------------------------------------
1. WHAT WE'RE BUILDING
----------------------------------------------------------------
A personal nutrition + weight-management app for Marco's own use.
NOT a calorie tracker. Core idea: GOAL MANAGEMENT — tracking exists only
to answer "Am I on track to hit my goal?"
Mental model: Goal → Weekly progress → Daily progress → Food/Activity inputs.

----------------------------------------------------------------
2. PLATFORM & STACK
----------------------------------------------------------------
React + Capacitor (web code + native iOS shell). NOT native Swift.
Stack: Vite 6, React 19, TypeScript, Tailwind CSS v4, Dexie (IndexedDB),
Vitest. Capacitor v8. appId: com.marco.nutritiongoal, webDir: dist.
Install path: Xcode + free Apple ID ($0). Re-sign every ~7 days.

----------------------------------------------------------------

  (1) no-goal  (2) active-normal  (3) final-day·no-weight

5. METRICS / MATH
----------------------------------------------------------------
Total Burn = BMR + Active Calories.
Daily Deficit = Total Burn − Calories Consumed.
~7700 kcal per kg for goal pace math.

ROUND 138 — MEAL NAME NOT STICKING + GRAMS-TO-SERVINGS RUNAWAY KCAL (2026-07-03)
Files: src/domain/{types,calc}.ts(+test), src/ui/components/AddEntrySheet.tsx
- Meal name edits never stuck: LogEntryContent.save()'s "stay a meal"
  branch wrote the edited name into mealData.name but never updated
  entry.manualName, which TodayScreen's Day's-log row reads FIRST — so the
  row (and reopened name field context) stayed frozen on whatever it was
  at first save. Fixed: manualName now kept in sync on every save
  (`saveToPantry ? undefined : mealName`), matching logBasket's first-save
  behavior.
- Grams silently became "servings" via the stepper (one meal hit 58,000
  kcal): MealItem never stored measurementType/referenceAmount, only a
  flattened TOTAL + optional plain qty multiplier. entryToBasket() always
  hardcoded reopened items to per_serving/referenceAmount:1 — "1 serving"
  secretly meant "the whole scanned total" — so each +0.5 stepper tap
  multiplied the ENTIRE total instead of nudging a few grams. Fixed by
  giving MealItem the same measurementType/referenceAmount treatment round
  136 gave FoodEntry: new items store a real RATE + qty (grams/servings);
  new mealItemNutrition() (calc.ts) scales correctly by that factor,
  wired into effectiveNutrition() and LogEntryContent.save()'s snapshot
  calc; entryToBasket() reconstructs the right measurementType/step on
  reopen. Older items (no measurementType) keep their exact old behavior —
  no migration needed. Bonus fix found in the same code: entryToBasket()
  never carried a linked ingredient's pantryItemId back into the edit
  basket, so resaving a meal with a pantry-linked ingredient silently
  unlinked it (or duplicated the Food item if "Save to pantry" was
  checked) — restored.
- tsc: clean. lint: clean. vitest: 48 passed (3 new). `npm run build`
  verified clean.

ROUND 137 — HDR PHOTO OVEREXPOSURE FIX (2026-07-03)
Files: src/lib/image.ts
- Marco noticed some captured photos looked "extra bright"/overexposed once
  saved. Root cause: downscaleImage/downscaleDataUrl (the two canvas-based
  photo-resize helpers) called getContext('2d') with no explicit color
  space. iPhone HDR/Deep Fusion photos carry a wide-gamut/HDR profile that
  WebKit's canvas has a known history of mis-tone-mapping when the color
  space isn't pinned, blowing out highlights — matches the "sometimes"
  pattern (only HDR-shot photos are affected). Fixed by passing
  { colorSpace: 'srgb' } explicitly to both getContext('2d') calls.
  NOTE: targeted fix for a documented WebKit quirk, not guaranteed 100% —
  needs Marco to confirm on a photo he knows came out too bright. Separately
  noted (not touched): PhotoPicker's native "Prompt" path bypasses this
  canvas pipeline entirely — if brightness shows up from that exact button
  too, that points to a different cause.
- tsc: clean. lint: clean. vitest: 45 passed. `npm run build` verified
  clean.

ROUND 136 — MANUAL ENTRY UNIT LOSS, MODAL SIZE, DECIMAL COMMA (2026-07-02)
Files: src/domain/{types,calc}.ts(+test), src/ui/components/AddEntrySheet.tsx,
       src/ui/components/MethodCards.tsx, src/ui/kit/NumberField.tsx
- Root cause of "saved as 100g, bumped to 400g, saved — converted to
  servings": manual entries (Nutri-scan/Describe/Photo/Manual — anything not
  picked from Pantry) only stored their flattened TOTAL, never their unit —
  entryToBasket() always rebuilt them as "1 serving = the total." Added
  manualMeasurementType/manualReferenceAmount to FoodEntry + new
  unscaleSnapshot() (calc.ts, tested, reverses nutritionFor()'s scaling).
  Wired into logBasket's fresh manual log, LogEntryContent's shrink/stay-
  manual save branches, and the unlink-to-local conversion (round 134).
  Older entries fall back to "1 serving" as before — no migration needed.
- MethodPickerModal: added an instructional caption + extra padding, taller
  per Marco's ask.
- NumberField: was type="number", which silently rejects a locale decimal
  comma outright (nothing to "convert" — the character never reaches
  onChange). Switched to type="text" + inputMode="decimal" with explicit
  comma-to-period normalization.
- tsc: clean. lint: clean. vitest: 45 passed. `npm run build` verified
  clean.
